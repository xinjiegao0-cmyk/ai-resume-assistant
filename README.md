# AI Resume Assistant · V10.0

面向计算机、AI 与互联网实习求职的简历分析工具。将简历与目标岗位描述（JD）放在一起，通过本地规则评分与 Kimi 语义分析，识别技能差距、梳理经历优势，并生成针对岗位的简历优化正文。

项目围绕「导入简历 → 输入 JD → 匹配分析 → 优化表达 → 回看记录」构建完整交互流程，展示 Python 应用开发、大模型 API 集成、可解释评分与界面设计能力。

## 核心功能

| 功能 | 当前实现 |
| --- | --- |
| 简历输入 | 支持粘贴文本，或上传 PDF、Word（`.docx`）、TXT；提取内容后可在文本框查看与编辑 |
| 技能画像 | 根据内置技能库识别编程语言、前端、后端、数据库、AI、开发工具、运营与设计技能，按类别展示标签 |
| 岗位匹配 | 展示综合匹配度、技能匹配、核心要求、关键词与 AI 语义分数，以及已匹配和待补强技能 |
| AI 分析 | 结合简历、JD 和本地评分，生成招聘判断、优势、短板与优化建议 |
| 简历优化 | 根据目标岗位调整表达和结构；提示词约束模型不得编造经历、技能、学历或成果数据 |
| 一键复制 | 使用 Streamlit 原生代码块右上角的复制图标，复制优化后的简历正文 |
| 历史记录 | 本地 JSON 保存最近 30 次分析，支持恢复对应简历、JD 与分析结果 |
| 设置 | 显示模型与 API Key 配置状态，支持清空当前会话的输入、分析和优化结果 |

### 文件支持范围

- **PDF**：通过 `pypdf` 逐页提取文本；适用于带文本层的 PDF，当前没有 OCR，扫描件需先转为文本。
- **Word**：通过 `python-docx` 读取 `.docx` 正文段落；不支持旧版 `.doc`，不提取表格中的内容，也不保留原文档排版。
- **TXT**：按 UTF-8 解码，忽略无法解码的字节。
- 优化结果以文本展示和复制，当前没有 PDF / Word 文件导出。

## V10.0 界面与 Liquid Glass 设计

采用深色背景、蓝紫渐变与半透明玻璃质感，突出输入、评分和分析结论三个信息层级。

- **七个视图**：首页、我的简历、目标岗位、AI 分析、优化简历、历史记录、设置。
- **玻璃卡片**：通过背景模糊、饱和度、细边框、内高光与阴影呈现层次；匹配技能与缺失技能使用不同颜色标签。
- **浮动 Dock**：以 Streamlit 原生侧边栏按钮完成导航，CSS 将其呈现为右侧固定 Dock，包含当前页高亮与悬停反馈。
- **小屏适配**：在宽度不超过 760px 时，CSS 将 Dock 调整为底部布局，并为内容预留底部空间。
- **样式组织**：页面基础样式位于 `app.py`；V10.0 Dock 与小屏适配样式独立存放于 `styles.css`。

## 工作流程与架构

当前采用单个 Streamlit 应用组织页面与业务函数，无独立后端服务。

```text
粘贴简历 / 上传 PDF、DOCX、TXT        输入目标岗位 JD
                  │                       │
                  └───────────┬───────────┘
                              ▼
                   Session State 保存输入
                              ▼
            本地分析：技能 / 核心要求 / 关键词 / 长度
                              ▼
               Kimi 语义分析：结合原文与本地结果
                              ▼
                 加权综合评分 + 分析结果展示
                      │               │
                      ▼               ▼
             JSON 历史记录       按岗位优化简历
             最近 30 次          展示正文并复制
```

主要函数：`read_uploaded_file` 负责文件解析，`local_analysis` 负责规则评分，`ai_analyze` 负责语义分析，`hybrid_analysis` 合并评分，`optimize_resume` 生成优化正文；各 `render_*` 函数负责页面展示。

### 匹配评分的实现思路

本地评分由四部分组成，权重在代码中固定：

```text
本地评分 = 技能匹配 × 40% + 核心要求 × 30%
         + 关键词匹配 × 20% + 简历长度指标 × 10%

综合评分 = 本地评分 × 45% + AI 语义分数 × 35%
         + AI 综合判断分数 × 20%
```

- **技能匹配**：用不区分大小写的子串匹配提取技能，计算 JD 中已识别技能的覆盖比例；JD 未识别出技能时默认记 50 分。
- **核心要求**：检查技能首次出现位置附近的文本，包含「要求」「掌握」「负责」「优先」等词时将该技能归入核心要求，再计算覆盖率；没有核心要求时沿用技能分。
- **关键词匹配**：正则提取英文词项和中文片段，过滤部分停用词；按 JD 词频计算覆盖度。高价值词权重为 2.2，其他长度至少为 4 的词项权重为 1.4，其余为 1.0。
- **简历长度指标**：按 `min(100, round(字符数 / 800 × 100))` 计算，代码中命名为 `completeness`；它只衡量长度，不检查教育、项目等章节是否齐全。

综合评分经取整并限制在 0–100。它是辅助比较的启发式指标，不是录用概率；当前没有基于招聘结果的评分校准，中文正则片段和技能子串匹配也可能产生漏识别或误匹配。

### AI 分析与回退

通过 OpenAI SDK 调用 Moonshot Chat Completions，将简历、JD、本地评分和技能差距一起送入模型，要求返回 JSON，包含语义分数、综合判断分数、总结、优劣势、缺失技能与建议。模型返回的面试风险和理由也会保存在分析数据中，当前页面未单独展示这两个字段。

未配置 Key、接口异常或结果无法解析为 JSON 时，分析会回退到本地评分，页面显示 AI 暂不可用。简历优化依赖模型成功返回，没有本地生成替代方案。防编造要求通过提示词表达，生成内容仍需结合本人经历核对。

## 项目亮点

- **可解释的混合分析**：本地规则提供可检查的技能覆盖与分项分数，大模型补充同义表达、经历迁移和岗位相关性的判断。
- **完整的使用链路**：覆盖输入、分析、优化、复制和历史恢复，让模型输出能够用于实际简历修改。
- **原生交互与定制视觉结合**：使用 Streamlit 原生组件承载导航和复制操作，CSS 统一玻璃质感与响应式 Dock。
- **本地评分可独立工作**：AI 不可用时仍能获得规则分析结果，方便无 Key 体验和定位匹配逻辑。

## 本地运行

建议使用 Python 3.11 创建独立环境。以下以 macOS / Linux 为例：

```bash
git clone https://github.com/xinjiegao0-cmyk/ai-resume-assistant.git
cd ai-resume-assistant
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

在项目根目录创建 `.env`，填写自己的凭据：

```dotenv
MOONSHOT_API_KEY=your_api_key_here
```

启动应用：

```bash
python -m streamlit run app.py
```

打开终端显示的本地地址，在「设置」中确认配置状态，然后导入简历并输入 JD。未配置 Key 时可体验本地匹配评分；AI 分析与简历生成需要有效凭据及网络连接。

### Streamlit Cloud 配置

部署入口为 `app.py`，依赖文件为 `requirements.txt`。在部署应用的 Secrets 中设置：

```toml
MOONSHOT_API_KEY = "your_api_key_here"
```

程序先读取环境变量（本地通过 `.env` 加载），未获取到时再读取 Streamlit Secrets。仓库内 `.streamlit/config.toml` 提供深色主题、无头服务与 XSRF 保护配置。

### 历史记录与数据边界

`analysis_history.json` 保存简历原文、JD、分数及分析结果，最多保留 30 条。清空当前分析数据只重置会话，不删除历史文件；历史记录也不保存生成后的优化正文。

当前历史文件由同一部署实例共享，没有账号或用户隔离；公开演示宜使用虚构示例资料。云端本地文件不保证持久保存。启用 AI 时，简历、JD 及分析上下文会发送至 Moonshot 接口。

`.env`、`.streamlit/secrets.toml`、`analysis_history.json` 和 Python 缓存已列入 `.gitignore`，不应提交到仓库。
